## 2. What the addon is
A World of Warcraft (retail, interface 120100, Lua 5.1) addon that judges gear ("is this item an upgrade?") for the
player's Main Spec / Off Spec, for three goals: Mythic+, Raid, PvP. Data is generated by GitHub Actions from public guide
data and shipped inside the addon (players update the addon; there is no in-game download).

Data flow:
1. `tools/classcodex_fetch.py` downloads the official ClassCodex build (public S3 manifest). `classcodex_build.py` merges
   two sources per field: **PvE (Mythic+/Raid) = Icy Veins guide data** (gear, trinkets, gems, enchants, talents,
   stat priority); **PvP = u.gg**; u.gg fills whatever Icy Veins lacks; `statTargets` = u.gg only.
2. `tools/classcodex_targets_cli.py` (+ `classcodex_targets.py`) runs SimulationCraft on the best-in-slot loadout of every
   spec x goal x hero tree (40 x 3 x 2 = 240 contexts) to get our own stat totals ("Measured" targets), for three gear
   levels (Myth 6/6 = ilvl 334, Hero 6/6 = 321, Champion 6/6 = 308; upgrade-track bonus-id swap table from game DB2 via
   `tools/upgrade_tracks.py`). Wowhead tooltips are a gear-only fallback for specs SimC cannot model (Holy Paladin,
   Restoration Shaman, Mistweaver, Holy Priest ...). Output `StatVerdict/Data/Generated/SV_ClassCodexTargets.lua`
   (compact Lua, <1 MB).
3. `tools/classcodex_weights_cli.py` computes measured stat weights (SimC scale factors), sharded in 6 jobs, output
   `SV_ClassCodexWeights.lua`. `SV_StatDR.lua` is the vendored diminishing-returns module.
4. Workflows: `classcodex-live-refresh.yml` (weekly Wed + manual, ~11 min; **verifies the new data with the addon
   integration tests before committing it**), `classcodex-stat-weights.yml` (1st/16th monthly, ~1 h), `tests.yml` (every
   push), `item-check.yml` (manual, see section 5).
5. Addon (Lua) in `StatVerdict/`: `Core/SV_ProfileRepository.lua` reads the generated files (hero tree resolved by
   subTreeID first, English name second); scoring in `Core/SV_Scoring.lua`, `SV_Modifiers.lua`;
   `Core/SV_ItemReferenceBonuses.lua` gives BiS / trinket-tier / Catalyst bonuses; UI in `UI/`.

## 3. Player-visible features (all agreed with the owner)
- **Mode drawer** (button "Mode"): rows **Guide** (default, pure copy of the guide: priority + u.gg target bin) and
  **Measured** (our own SimC targets + measured weights). The 3 cards below mean: in Guide "Tier 1/2/3" (= u.gg
  top80/top50/top20, `StatVerdictDB.statTargetBin`); in Measured "Champion/Hero/Myth" (gear level,
  `StatVerdictDB.gearLevel`, swaps upgrade-track bonus ids in Best in Slot / Ranked Trinkets and picks `targets.levels`).
  Hidden slash command `/svweights guide|measured`.
- **Best in Slot / Ranked Trinkets** panels; hover on a BiS row shows our own compact tooltip (item name, ilvl, upgrade
  track, stats, "Part of the tier set", then "Recommended": gems + enchant; the unique primary gem only on the first
  socketed slot). Features drawer has 3 options: own tooltip (default) / gems and enchants / use the game tooltip
  (first and third switch each other off).
- **Catalyst rule**: if the BiS piece for head/shoulders/chest/hands/legs is a tier-set piece, any found item with an
  upgrade track counts like BiS and gets the line "Good if converted to the set piece with the Catalyst".
- Only ONE best gem/enchant is recommended (no alternatives — decided).
